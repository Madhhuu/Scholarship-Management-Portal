# Day 2 – Requirement Analysis and Java Class Design

## 1. Objective
To understand the functional requirements of the Scholarship Management Portal and identify the main classes required for its initial implementation.

## 2. Requirement Analysis
The portal is intended to support four major user roles:

- **Admin:** Manages scholarship schemes and views reports.
- **Student:** Views scholarships and submits applications.
- **Institute Verifier:** Verifies student applications and supporting documents.
- **Sanctioning Officer:** Approves eligible applications and records sanction details.

## 3. Functional Requirements Identified
- Publishing and managing scholarship schemes.
- Viewing scholarship details and eligibility criteria.
- Submitting scholarship applications.
- Verifying submitted applications.
- Approving scholarship amounts.
- Tracking application status.
- Generating scheme-wise reports.

## 4. Non-Functional Requirements Identified
- Preventing duplicate applications for the same scheme and academic year.
- Protecting sensitive student and income information.
- Restricting document access to authorized users.
- Enforcing application deadlines.
- Maintaining reliable and consistent application records.

## 5. Java Class Design
Identified the following classes for the initial Java implementation:

- **Student:** Represents student information.
- **Scholarship:** Stores scholarship ID, name, amount, and eligibility criteria.
- **Application:** Represents a student's scholarship application.

## 6. Tasks Performed
- Studied the project workflow.
- Identified the major user roles and system requirements.
- Organized the project using separate Java class files.
- Reviewed basic object-oriented programming concepts such as classes, objects, constructors, and methods.

## 7. Learning Outcomes
Learned how requirement analysis helps define system functionality and how class design represents real-world entities in Java.

## 8. Outcome
The main project requirements and initial Java class structure were identified for further implementation.
